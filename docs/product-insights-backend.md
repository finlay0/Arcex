# Product insights backend

Coverage defaults to `signals`. An owner marks `full` through `PUT /api/v1/admin/products/:id/coverage` with `level` and review `notes`. This requires approved capture evidence and an approved image from an app stage beyond its landing page. This is an editorial scope decision, not an automated claim of complete authenticated coverage. Replacing the funnel, changing paywall mechanics, retracting evidence or withdrawing an image resets that review. Partial captures and their annotations remain unavailable from public Signals Only responses.

Full Screens allows ten distinct free apps per UTC day; reopening costs nothing. Insider and the designated open sample bypass that cap. Unsigned media is denied. An authenticated viewer who already opened an app can POST `{ "position": 0 }` to `/api/v1/vault/:slug/share` for a seven-day signed link to that one screen. Changing a position, step ID, product or media ID invalidates its signature. Replacing captures invalidates old screen links. The frontend should use this returned URL rather than constructing bare `?step=` links.

Metrics are cached in resumable pages of 25 every ten minutes. At 10,000 published products a cache cycle takes under three days. One timer also supports bounded source enqueueing when explicitly enabled; source collection currently remains paused. This reuses Arcex's existing cron slot within the Workers Free account limit. Activity history describes observed advertising and creator activity, not company growth. Missing collection remains null. Revenue ranges are manually reviewed, versioned source-backed ranges; no computed revenue model is implemented.

Watch lists support three free products and paginated unlimited Insider products. Changes require approved evidence and explicit publication. Resend delivery is configured and enabled after a deployed-Worker simulator test and independent provider receipt check. Real customer inbox delivery has not been tested. Digests require opt-in, current Insider access, a watched published product and approved published changes. Daily/monthly attempt limits stop delivery without paid fallback. Users can disable the preference after losing Insider access. See [email operations](email-alerts.md).

Public-page metadata checks now create private `public_page` change drafts after a saved baseline changes. Each comparison retains both evidence IDs. The first check and unchanged checks produce no event. This covers title, description and headings, not every page pixel or authenticated state. Existing sources establish a baseline on their first observed check after this migration. The baseline survives job retention cleanup. Before/after evidence must both be approved before publication and remain approved for public feeds or email. Retracting either side hides the comparison.

Owner review uses bounded `GET /api/v1/admin/changes?status=draft&productId=...`, `PUT /api/v1/admin/changes/:id` with a factual summary, and the existing explicit status endpoint. Work reads recent comparison IDs through `read_product_research`; it cannot publish them. The HTTP collector is still a supervised Node runner, and recurring research remains paused. Automatic metadata comparison does not imply unattended cloud collection or automatic detection of all ads, pricing and flow changes.

The Google backend sign-in flow has passed a real consent/session test on api.arcex.dev. The frontend should use that API base with credentials included. The existing workers.dev private Collector OAuth origin remains intact; GitHub's separate same-site web callback migration is still pending.
